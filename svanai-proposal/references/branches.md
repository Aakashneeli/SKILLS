# Proposal branches

Branch on three independent axes. Do not force them into one flat proposal type.

## Engagement axis

### Discovery or consulting

Focus on questions, workshops, analysis, decision artifacts, recommendations, and discovery acceptance. Frame implementation as a possible next phase, not a current commitment.

### Paid POC

Define hypotheses, constrained data and workflows, success metrics, demo conditions, evaluation limits, and the production decision that follows.

### MVP

Prioritize must-have outcomes, explicitly defer broader production features, define a usable validation environment, and set MVP acceptance.

### Production implementation

Cover deployment, scalability parameters, security or operational constraints, UAT, governance, handover, warranty, and support.

### Support or retainer

Replace the implementation roadmap with monthly capacity, service categories, request workflow, response expectations, exclusions, reporting, and a recurring fee.

## Prior-POC context axis

- `new`: establish the problem and evidence without claiming prior validation.
- `successful-poc`: include approved POC evidence, state what has been proven, and focus the investment on production scope, control, and scalability.

## Commercial axis

- `phase-hourly`: show phase, description, hours, client billing rate, and amount.
- `fixed-sow`: show fixed deliverables, price, milestone payments, acceptance, and formal change control.
- `value-based`: compare with cost-derived pricing privately and show only the selected client price.
- `packages`: add two or three packages only when the user confirms that choice and each tier represents a meaningful scope decision.

## IP axis

- `client-owned`: assign project-specific deliverables after full payment; retain SvanAI pre-existing IP.
- `svanai-owned-license`: retain ownership and define the client's license.
- `custom`: state that ownership is jointly or separately negotiated; use only user-approved wording.

## Core sections

Use these unless the branch makes one irrelevant:

1. Cover
2. Executive summary
3. Understanding the business
4. Solution vision or engagement approach
5. Proposed solution or deliverables
6. Functional scope, acceptance, assumptions, and responsibilities
7. Delivery roadmap or service plan
8. Commercial proposal with detailed development costs
9. Why svanAI
10. Support, governance, and terms
11. Next steps

Allow any page count. Split dense sections or merge short adjacent sections while preserving reading order and the SvanAI section rhythm.
